## Content Security Policy (CSP)

### Overview

Content Security Policy is implemented to prevent cross-site scripting (XSS), code injection, and other security vulnerabilities. The CSP is configured in `next.config.ts` as HTTP headers.

### CSP Directives Implemented

```typescript
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'unsafe-eval' 'unsafe-inline' https://js.monitor.azure.com;
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:;
  font-src 'self' data:;
  connect-src 'self' https://*.applicationinsights.azure.com https://*.in.applicationinsights.azure.com;
  worker-src 'self' blob:;
  object-src 'none';
  embed-src 'none';
  base-uri 'self';
  form-action 'self';
  frame-ancestors 'self';
  upgrade-insecure-requests
```

### Directive Explanations

**default-src 'self'**

- Restricts loading of resources to same origin by default
- Prevents loading external scripts, styles, or resources unless explicitly allowed

**script-src 'self' 'unsafe-eval' 'unsafe-inline' https://js.monitor.azure.com**

- Allows scripts from same origin
- `'unsafe-eval'` required for Next.js development and some runtime features
- `'unsafe-inline'` required for Next.js inline scripts and Application Insights
- `https://js.monitor.azure.com` for Azure Application Insights SDK

**style-src 'self' 'unsafe-inline'**

- Allows stylesheets from same origin
- `'unsafe-inline'` required for Tailwind CSS and styled-jsx (Next.js)

**img-src 'self' data: blob:**

- Allows images from same origin
- `data:` for base64-encoded images generated by html2canvas
- `blob:` for blob URLs created during print operations

**font-src 'self' data:**

- Allows fonts from same origin
- `data:` for embedded fonts in CSS

**connect-src 'self' https://\*.applicationinsights.azure.com**

- Allows AJAX/fetch requests to same origin
- Application Insights domains for telemetry data

**worker-src 'self' blob:**

- Allows web workers from same origin
- `blob:` for dynamically created workers (html2canvas)

**object-src 'none'** and **embed-src 'none'**

- Blocks all plugins (Flash, Java, etc.) for security

**base-uri 'self'**

- Restricts base tag to same origin (prevents base tag injection)

**form-action 'self'**

- Restricts form submissions to same origin

**frame-ancestors 'self'**

- Controls where the page can be embedded (same as X-Frame-Options: SAMEORIGIN)

**upgrade-insecure-requests**

- Automatically upgrades HTTP requests to HTTPS in production

### Why 'unsafe-inline' and 'unsafe-eval'?

While these directives reduce CSP effectiveness, they're necessary for:

1. **Next.js Framework Requirements**:
   - Next.js uses inline scripts for hydration
   - Dynamic imports require eval-like behavior
   - styled-jsx uses inline styles

2. **Application Insights**:
   - SDK uses inline script initialization
   - Dynamic telemetry requires inline execution

3. **html2canvas**:
   - Canvas rendering uses blob workers
   - Image generation uses data URLs

### Production CSP Hardening

For production deployments, consider:

1. **Nonce-based CSP**:

   ```typescript
   // Generate nonce for each request
   const nonce = generateNonce();
   script-src 'self' 'nonce-${nonce}';
   ```

2. **Hash-based CSP**:

   ```typescript
   // Pre-compute hashes of inline scripts
   script-src 'self' 'sha256-...';
   ```

3. **Remove 'unsafe-inline' gradually**:
   - Extract inline styles to external CSS files
   - Use nonces for necessary inline scripts
   - Report violations before enforcing

### Additional Security Headers

The application also implements:

- **X-Frame-Options: SAMEORIGIN** - Prevents clickjacking
- **X-Content-Type-Options: nosniff** - Prevents MIME sniffing
- **Referrer-Policy: strict-origin-when-cross-origin** - Limits referrer information
- **Permissions-Policy** - Restricts browser features (camera, microphone, geolocation)
- **Strict-Transport-Security** - Forces HTTPS (production only)

### CSP Reporting

To enable CSP violation reporting:

```typescript
// Add to CSP header
report-uri /api/csp-report;
report-to csp-endpoint;
```

Then create an API route to log violations:

```typescript
// app/api/csp-report/route.ts
export async function POST(request: Request) {
  const report = await request.json();
  console.error('CSP Violation:', report);
  return new Response('OK', { status: 200 });
}
```

### Testing CSP

1. **Browser Console**: Check for CSP violations in browser DevTools console
2. **CSP Evaluator**: Use Google's CSP Evaluator tool
3. **Report-Only Mode**: Test changes without blocking

```typescript
// Test new CSP rules without blocking
Content-Security-Policy-Report-Only: ...
```

## ESLint Configuration

### Overview

ESLint is configured with comprehensive rules for TypeScript, React, Next.js, accessibility, and security best practices.

### Configuration File

The configuration is in `eslint.config.mjs` using the new flat config format.

### Enabled Rule Sets

1. **Next.js Core Web Vitals**
   - Performance best practices
   - React optimization rules

2. **Next.js TypeScript**
   - TypeScript-specific rules
   - Type safety enforcement

3. **TypeScript ESLint**
   - Type checking rules
   - TypeScript best practices

4. **Prettier Integration**
   - Automatically formats code
   - Prevents style conflicts

### Key Rules Enabled

#### TypeScript Rules

```javascript
'@typescript-eslint/no-explicit-any': 'warn'
'@typescript-eslint/no-unused-vars': ['warn', { argsIgnorePattern: '^_' }]
```

#### Best Practices

```javascript
'no-console': ['warn', { allow: ['warn', 'error'] }]
'no-debugger': 'error'
'no-alert': 'warn'
'no-eval': 'error'
'no-implied-eval': 'error'
```

#### React Rules

```javascript
'react/prop-types': 'off' // TypeScript handles this
'react/react-in-jsx-scope': 'off' // Not needed in Next.js
'react-hooks/rules-of-hooks': 'error'
'react-hooks/exhaustive-deps': 'warn'
```

#### Accessibility Rules

```javascript
'jsx-a11y/anchor-is-valid': 'error'
'jsx-a11y/aria-props': 'error'
'jsx-a11y/role-has-required-aria-props': 'error'
```

#### Security Rules

```javascript
'no-unsafe-finally': 'error'
'no-unsafe-negation': 'error'
```

### Running ESLint

```bash
# Check for issues
npm run lint

# Fix auto-fixable issues
npm run lint:fix
```

### Ignoring Files

ESLint ignores:

- `.next/**` - Build output
- `node_modules/**` - Dependencies
- `coverage/**` - Test coverage
- `*.config.js` - Config files
- `public/**` - Static assets

### VSCode Integration

Install the ESLint extension and add to `.vscode/settings.json`:

```json
{
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true
  },
  "eslint.validate": ["javascript", "javascriptreact", "typescript", "typescriptreact"]
}
```

## Prettier Formatting

### Overview

Prettier enforces consistent code formatting across the entire codebase, eliminating style debates and ensuring readability.

### Configuration File

Settings are in `.prettierrc.json`:

```json
{
  "semi": true,
  "trailingComma": "es5",
  "singleQuote": true,
  "printWidth": 100,
  "tabWidth": 2,
  "useTabs": false,
  "arrowParens": "always",
  "endOfLine": "lf",
  "bracketSpacing": true,
  "jsxSingleQuote": false,
  "proseWrap": "preserve"
}
```

### Configuration Explanation

- **semi**: true - Always use semicolons
- **trailingComma**: "es5" - Trailing commas where valid in ES5
- **singleQuote**: true - Use single quotes instead of double
- **printWidth**: 100 - Wrap lines at 100 characters
- **tabWidth**: 2 - Use 2 spaces for indentation
- **useTabs**: false - Use spaces, not tabs
- **arrowParens**: "always" - Always include parens in arrow functions
- **endOfLine**: "lf" - Use LF line endings (Unix-style)
- **bracketSpacing**: true - Spaces inside object literals
- **jsxSingleQuote**: false - Use double quotes in JSX
- **proseWrap**: "preserve" - Don't wrap markdown text

### Running Prettier

```bash
# Format all files
npm run format

# Check formatting without modifying files
npm run format:check
```

### Ignoring Files

Prettier ignores files listed in `.prettierignore`:

- `node_modules/`
- `.next/`
- `out/`
- `build/`
- `coverage/`
- Generated files

### VSCode Integration

Install the Prettier extension and add to `.vscode/settings.json`:

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true
}
```

### Pre-commit Hook (Optional)

To automatically format on commit, install husky and lint-staged:

```bash
npm install --save-dev husky lint-staged
npx husky init
```

Add to `package.json`:

```json
{
  "lint-staged": {
    "*.{js,jsx,ts,tsx}": ["eslint --fix", "prettier --write"],
    "*.{json,md,yml,yaml}": ["prettier --write"]
  }
}
```

## Troubleshooting

### Common Issues

**1. ESLint errors after pulling changes**

```bash
# Clear cache and reinstall
rm -rf node_modules .next
npm install
```

**2. Prettier conflicts with ESLint**

```bash
# Ensure eslint-config-prettier is installed
npm install --save-dev eslint-config-prettier
```

**3. CSP violations in browser**

Check browser console for specific violations:

```
Refused to load the script 'https://example.com/script.js' because it violates the following Content Security Policy directive: "script-src 'self'"
```

Update CSP to allow the domain if legitimate.

**4. Type errors in tests**

```bash
# Ensure test types are installed
npm install --save-dev @types/jest
```

**5. Formatting breaks on Windows**

Ensure `endOfLine` is set correctly in `.prettierrc.json`:

```json
{
  "endOfLine": "auto" // or "crlf" for Windows
}
```

### Debug Mode

Enable verbose ESLint output:

```bash
npm run lint -- --debug
```

Enable Prettier debugging:

```bash
npm run format -- --loglevel debug
```

## Best Practices

### Code Quality

1. **Write self-documenting code** - Use clear variable and function names
2. **Keep functions small** - Aim for single responsibility
3. **Use TypeScript strictly** - Avoid `any` type
4. **Write tests first** - TDD approach when possible
5. **Document complex logic** - Add comments for non-obvious code

### Security

1. **Never disable CSP** - Adjust policies instead of removing them
2. **Validate all inputs** - Both client and server side
3. **Sanitize user data** - Prevent XSS and injection attacks
4. **Use HTTPS everywhere** - In production, enforce HTTPS
5. **Regular dependency updates** - Keep packages up to date

### Performance

1. **Code splitting** - Use dynamic imports for large components
2. **Optimize images** - Use Next.js Image component
3. **Memoization** - Use React.memo, useMemo, useCallback appropriately
4. **Lazy loading** - Load components and data on demand
5. **Monitor bundle size** - Keep initial load under 200KB

### Accessibility

1. **Use semantic HTML** - header, nav, main, footer, section
2. **ARIA attributes** - When semantic HTML isn't enough
3. **Keyboard navigation** - All interactive elements accessible
4. **Color contrast** - WCAG AA minimum (4.5:1)
5. **Test with screen readers** - NVDA, JAWS, VoiceOver
